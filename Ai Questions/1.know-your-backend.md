## Phase 0: Tool Setup, AI Ko Repo Dikhane Ka Tareeka

Pehle tool set karo, phir niche ka Master Prompt paste karo.

| Tool                           | Setup                                                                                                   | Read-only mode                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Claude Code                    | Repo root me `claude` chalao                                                                            | Plan mode on karo (Shift+Tab), ya bol do "sirf padh, kuch change na kar" |
| Cursor                         | Repo open karo, Chat/Composer me "Agent" ki jagah "Ask" mode choose karo                                | Ask mode khud read-only hai                                              |
| GitHub Copilot (VS Code)       | Copilot Chat open karo, `@workspace` se poora repo context do                                           | Ask mode use karo, Edit/Agent mode nahi                                  |
| ChatGPT / Claude.ai (web chat) | Repo folder dikha nahi sakte, isliye poora repo ek text file me pack karo: `npx repomix` ya `gitingest` | Web chat khud hi read-only hai, kuch run nahi kar sakta                  |

**Safety rule sabke liye same:** AI ko kabhi mat dena ki wo khud se install, migration, `docker up`, ya koi bhi command chalaye. Pehle command dikhaye, phir tu chalaye.

## Phase 1: AI Ka Mahol Set Karo (Persona + Rules)

```
Bhai sun, tu mera bada bhai hai, apna banda hai. Tone chill aur dost jaisi
rakhna, lekin content 100% technical aur precise hona chahiye. Jahan doubt
lage wahan real example deke samjha.

Content rules:
1. Full understanding: Jawab dene se pehle poora sawaal samajh, confuse ho
   toh pooch le, guess mat kar.
2. Proper research: Code khud padh ke verify kar, apni training memory se
   mat bol.
3. Proof rule: Har claim ke saath exact file aur line number bata (file:line).
   Code me nahi mila toh "Not found in code" bol.
4. Fact vs assumption: Jo code me likha hai wo "Fact" bol, jo tu estimate ya
   guess kar raha hai wo "Assumption" bol. Dono ko alag line me mark kar.
5. Aim for correctness: Sirf jawab dena kaafi nahi, jawab correct aur precise
   hona chahiye.
6. Read-only: Koi bhi command, install, migration ya file change khud se mat
   chala. Sirf suggest kar, main chalaunga.
7. Stack-neutral: Project jo bhi language/framework use kare (Node, Go, Rust,
   Java, Python, kuch bhi), usi ke hisaab se jawab de. Mera koi fixed
   expectation nahi hai, repo me jo hai wahi bata.
8. Phase stop: Ek phase khatam karke ruk ja aur "next phase?" pooch. Saari
   baatein ek message me mat de.

Format rules:
- Crisp by default: Pehle 3-4 line ka seedha jawab de. Full, engineering-level
  detail sirf tab de jab mai clearly maangu.
- Easy words: Simple bhasha use kar, bina zaroorat ke jargon mat de.
- Points and tables: Paragraph mat likh, bullets ya table me de, lines ke
  beech gap rakh.
- No em-dash: Em-dash (—) use mat kar, comma ya period se tod.
- No hurry: Jawab dene me jaldi mat kar, pehle poora socha-samjha de.

Ready ho jaa. Mai tujhe is repo ke baare me phase by phase sawaal karunga.
```

**Output chahiye:** AI confirm kare ki rules samajh gaya.
**Done check:** AI ne rules apne shabdon me repeat kar diye, agle phase pe badho.

## Phase 2: Project Kya Hai, Ek Line Me Samjho

```
Ye project karta kya hai? One-liner me bata. Real-life example de (kisi
dukaan, app ya daily routine se related kare). End user kaun hai: customer,
developer ya admin? Core value kya hai, ye kis problem ko solve karta hai?
```

**Output chahiye:** 4-5 line ka plain answer, jargon nahi.
**Done check:** Tu bol paye "ye project X karta hai, Y ke liye".

## Phase 3: Real Folder Tree Aur Tech Stack Dekho

```
Repo ka actual folder tree dikha (root se 2-3 level deep), fake ya example
tree nahi, jo yaha hai wahi. Har top folder ka 1-line purpose bata. Phir
dependency file (package.json / go.mod / Cargo.toml / pom.xml /
requirements.txt, jo bhi ho) padh ke exact language version aur main
dependencies bata, file:line ke saath. Dependencies me DB client, cache
client, queue client aur third-party SDK alag se highlight kar. Entry point
file kaunsi hai aur server start hote hi kya hota hai (DB connect, middleware
order, config load)?
```

**Output chahiye:** Real tree + dependency table (naam, version, kaam, type: DB/cache/queue/third-party) + entry point ka file:line.
**Done check:** Tree aur stack dono repo ki asli files se match karte hain.

## Phase 4: Project Apne System Pe Chalao

```
Repo ke apne scripts/docs se (README, Makefile, package.json scripts, ya jo
bhi config file ho) exact prerequisites aur run steps nikal. Mera koi fixed
tool mat maan, repo jo bhi use kare wahi bata. .env.example ya config sample
file hai kya? Agar hai toh har variable ka purpose 1 line me bata. Agar koi
step file me clearly nahi likha, "Not found" bol, apna guess mat de.
```

**Output chahiye:** Step by step run checklist, file:line reference ke saath.
**Done check:** Tu wahi command repo me chala ke dekh paya. Error aaye toh AI se wahi file:line dikha ke pooch.

## Phase 5: Ek Request Ka Pura Safar Trace Karo

```
Koi ek real API ya entry flow choose kar (sabse zyada use hone wala). Uska
poora path trace kar: request kaha se aata hai -> kaunsa function/handler
pakadta hai -> beech me kya-kya calls hoti hai -> DB/cache kaha touch hota hai
-> response kaise banta hai. Har step pe file:line de. Last me isi flow ka
Mermaid sequence diagram bana (text se, GitHub/VS Code me render hota hai).
```

**Output chahiye:** Step list file:line ke saath + Mermaid diagram.
**Done check:** Diagram code se match karta hai, ek bhi step miss nahi.

## Phase 6: Saare APIs Aur Communication Ka Tarika Dekho

```
Repo ke sab routes/endpoints ek table me laa: method, path, handler
(file:line), auth chahiye ya nahi. Phir bata ye REST hai, WebSocket, gRPC,
GraphQL, queue consumer, webhook ya SSE, jo bhi actually code me mile. Kisi
bhi protocol ko suggest mat kar jo code me nahi hai. API docs (Swagger/
Postman/README) hai kya? Nahi hai toh bol "nahi hai", khud se bana mat de jab
tak main na kahu.
```

**Output chahiye:** Route table + protocol list (sirf jo mile) + docs status.
**Done check:** Table ke har row ka file:line verify ho gaya.

## Phase 7: Database Schema Aur Relations Samjho

```
Database schema/models dikha: tables ya collections, fields, relations,
indexes. Migrations folder hai kya? Transactions kaha use hoti hai? Sab
file:line ke saath. Fixed example mat de, jo is repo me actually defined hai
wahi bata.
```

**Output chahiye:** Schema table + relations + index list, sab file:line ke saath.
**Done check:** Schema fields real model file se match karte hain.

## Phase 8: DB Scaling Dekho (Replication Aur Sharding)

```
Phase 7 ke schema se aage dekh: read replica ka config ya connection string
kahi hai kya? Sharding ya partition key kahi defined hai kya (DB config,
connection pool, env variable)? Primary-secondary ya master-slave setup ka
zikr code me hai kya? Jo nahi mila, "abhi single DB instance lagta hai,
scaling setup code me nahi mila" bol. Khud se replication/sharding maan mat
lena.
```

**Output chahiye:** Replica/shard config status, file:line ya "nahi mila".
**Done check:** Scaling setup ka status proof-based hai, guess wala nahi.

## Phase 9: Auth, Errors, Logging, Cache, Jobs Check Karo

```
Ye sab check kar, jo mile wahi bata, jo na mile "nahi hai" bol:
- Auth: kaunsa method (JWT/session/OAuth), file:line
- Validation: input galat aaye toh kya hota hai
- Error handling: errors kaha catch hote hai, response format kya hai
- Logging: kaunsi library, logs kaha jaate hai
- Cache: kaha use hota hai, kyu
- Background jobs: queue/cron/workers hai kya
- Config: env variables kaha load hote hai
- Analytics: user actions track hote hai kya
```

**Output chahiye:** Table, 8 rows, har row file:line ya "not found".
**Done check:** Har cross-cutting concern ka status clear hai.

## Phase 10: Caching Strategy Deep-Dive Karo

```
Phase 9 me jo cache mila, uska poora lifecycle trace kar: cache-aside hai ya
write-through (code me set/get ka order dekh ke bata)? TTL kitna set hai,
file:line ke saath? Cache invalidate kab hota hai (update/delete pe clear
hota hai kya)? Cache miss pe kya hota hai? Agar Phase 9 me cache "nahi hai"
bola tha, ye phase skip kar aur bol "cache hi nahi hai, deep-dive nahi ho
sakta".
```

**Output chahiye:** Pattern (cache-aside/write-through), TTL, invalidation trigger, sab file:line ke saath.
**Done check:** Cache ka pura lifecycle (set, get, invalidate) trace hua, guess nahi.

## Phase 11: Kaunse Third-Party Tools Use Hue Hai

```
Repo me use hue sab third-party services/SDKs list kar (code se, guess nahi).
Har ek ka purpose 1 line me bata, file:line ke saath jaha use hua. Pricing ya
free-tier limit AI ki training data se purana ho sakta hai, isliye wo number
khud official site se verify karna, AI se sirf naam aur purpose le.
```

**Output chahiye:** Table: service, purpose, file:line.
**Done check:** Pricing wali baat tu official site se verify kar le, AI ke number pe depend mat kar.

## Phase 12: System Design Diagram Banao (HLD + LLD)

```
Ab tak jo explore hua (map, run, trace, APIs, data layer, DB scaling, cross-
cutting, caching, third-party) usi se do Mermaid diagram bana:

1. High Level Design: client se lekar DB/cache/queue/third-party tak sab
   real components, jo abhi tak file:line se confirm hue hai.
2. Low Level Design: koi ek real feature choose kar (sabse zyada use hone
   wala, ya jo Phase 5 me trace kiya tha), uska module interaction diagram.

Design pattern sirf tab bata jab code me clearly identify ho, generic pattern
naam (MVC/Singleton) force mat kar. Dono diagram sirf verified components se
bane, guess wala component mat daal.
```

**Output chahiye:** 2 alag Mermaid diagram (HLD, LLD), clearly labeled.
**Done check:** Dono diagram repo ke actual files/folders se map hote hai.

## Phase 13: Failure Handling Dekho (Retry, Timeout, Fallback)

```
Phase 12 ke HLD diagram me jo components hai (DB, cache, queue, third-party),
unme se ek-ek karke pooch: "agar ye component down ho jaye, code me kya hota
hai?" Retry logic hai kya (kitni baar, kitna gap), file:line? Timeout set hai
kya? Idempotency handle hoti hai kya (duplicate request safe hai)? Circuit
breaker ya fallback hai kya? Jo nahi mila, "nahi hai" bol, khud se resilience
maan mat lena.
```

**Output chahiye:** Table (component, retry/timeout/fallback status, file:line ya "nahi hai").
**Done check:** Har component ka failure-case status proof-based hai.

## Phase 14: Observability Dekho (Metrics, Tracing, Alerts)

```
Logging se aage dekh: metrics collect hote hai kya (Prometheus, StatsD,
custom counter)? Distributed tracing hai kya (OpenTelemetry, Jaeger, trace-id
request me propagate hota hai)? Dashboard ya alert rule config kahi hai kya
(Grafana config, alert threshold)? Jo nahi mila "nahi hai" bol.
```

**Output chahiye:** Metrics/tracing/alerting status, file:line ya "nahi hai".
**Done check:** Observability ka status real config se verified hai, guess nahi.

## Phase 15: Tests Aur Security Check Karo

```
Tests hai kya (unit/integration/e2e)? Kaunsi library, test files kaha hai,
run command kya hai. Naming convention consistent hai kya? Security quick
check: hardcoded secrets, rate limiting, CORS config, obvious injection risk,
sab file:line ke saath bata ya "nahi mila" bol.
```

**Output chahiye:** Test status + security checklist, dono file:line ke saath.
**Done check:** Koi bhi security point bina proof ke nahi likha gaya.

## Phase 16: Rate Limiting Deep-Dive Karo

```
Phase 15 me jo rate limiting mila, uska deep dive kar: algorithm kaunsa hai
(fixed window, sliding window, token bucket, leaky bucket), code se identify
kar, file:line. Limit kitna hai (per user/IP/API key)? Limit cross hone pe
kya response aata hai (status code, retry-after header)? Agar Phase 15 me
rate limiting "nahi mila" bola tha, ye phase skip kar aur bol "rate limiting
hi nahi hai, algorithm discuss nahi ho sakta".
```

**Output chahiye:** Algorithm naam + limit value + response behavior, file:line ke saath.
**Done check:** Agar rate limiting nahi hai to AI ne khud se algorithm nahi bana diya.

## Phase 17: Ship, CI Aur AI/Quality Gates Dekho

```
Repo root aur dotfiles/config folders me dhoond, jo mile file:line ke saath
bata, jo na mile "nahi hai" bol:
- Deploy: code prod tak kaise jaata hai (Dockerfile, CI/CD workflow, deploy
  script)
- CI pipeline: push/PR pe kya-kya chalta hai (lint, test, build, security
  scan), kaunsa step merge ko block karta hai
- Static analysis / quality gate: SonarQube, Codacy, DeepSource ya similar
  tool ka config hai kya, kya rule/threshold set hai
- AI PR review bot: CodeRabbit, Copilot code review ya similar bot ka config
  hai kya
- AI agent rules: CLAUDE.md, AGENTS.md, .cursor/rules, .github/copilot-
  instructions.md ya koi aur AI policy file, inme kya restriction likhi hai
- Hooks: git hooks (pre-commit/pre-push) ya AI tool hooks (jaise Claude Code
  ka PreToolUse) kya block karte hai
- Health check: `/health` ya similar endpoint hai kya
- Git history: last 10-15 commits dekh, koi bada decision pattern mile toh
  1 line me bata
```

**Output chahiye:** Table (tool/file, purpose, file:line) + "nahi mila" list.
**Done check:** Har row file:line se verified, kuch bhi training-memory se guess nahi hua.

## Phase 18: Load Aur Scaling Ka Andaza Lagao

```
Current code me in-memory state kaha hai (ye horizontal scaling rokta hai)?
Bottleneck kaha dikh raha hai code se (DB query, single server assumption,
etc)? User count ka exact number guess mat kar, bol "iska estimate sirf load
test se milega". Load test kaise set karu (k6 ya similar) ye suggest kar
sakta hai.
```

**Output chahiye:** In-memory state list + bottleneck list (file:line), load-test suggestion.
**Done check:** Koi bhi "X users handle karega" wala number bina data ke nahi aaya.

## Phase 19: Back-of-Envelope Capacity Estimate

```
Capacity planning ke liye mujhe sirf facts de, final maths mai khud karunga:

1. Record size: DB schema se (jo Phase 7 me dekha) ek typical record/row/
   document ka average size estimate kar (field types se), file:line ke
   saath.
2. Response size: Ek typical API response (jo Phase 6 me dekha) ka average
   size kitna hai, field count se estimate kar.
3. Read:Write ratio: Routes me kitne GET (read) hai aur kitne POST/PUT/
   DELETE (write) hai, count kar ke ratio bata.
4. Latency reference: Ye 4 number yaad dila (general engineering knowledge,
   code se nahi aata): RAM read ~100ns, SSD read ~100 microsec, same-
   datacenter network round trip ~1ms, cross-region round trip ~100ms.

User count, QPS, bandwidth aur storage growth khud se guess MAT kar, ye mai
khud decide karunga (jaise "1 lakh users, 10% daily active"). Jab mai apna
number du, tu sirf maths verify karna: QPS, bandwidth, storage sab formula
se nikal ke dikha.
```

**Output chahiye:** Record size + response size + read:write ratio (file:line ke saath) + latency reference table.
**Done check:** Tu khud user-number de ke QPS/storage/bandwidth calculate kar paya, AI ne koi number khud se nahi thopa.

## Phase 20: Critique Aur Redesign Kar

```
Ab tak jo sab dekha (map, data, DB scaling, cross-cutting, caching, third-
party, diagram, failure handling, scale) usi ke base pe bata: agar tu khud se
is feature/system ko design karta, kya 2-3 cheezein different karta aur kyu?
Current design ka sabse weak link kya lagta hai tujhe? Koi ek trade-off jo
current design ne liya hai, uska alternative kya tha? Ye sab tera "Opinion"
hai, "Fact" nahi, isliye clearly "Opinion" mark karke bata.
```

**Output chahiye:** 2-3 redesign suggestions + weakest-link opinion, "Opinion" clearly mark karke.
**Done check:** Suggestions is repo ki real architecture pe based hai, generic textbook advice nahi.

## Phase 21: Khud Check Karo Ki Samjha Ya Nahi

```
Mujhse 5 sawaal pooch jo isi codebase pe based ho, taki pata chale maine
samjha ya nahi. Phir ek chhota, safe change suggest kar (jaise ek log line ya
comment add karna) jo mai khud karke dekhu. Last me ek onboarding notes file
likh, sirf jab mai permission du.
```

**Output chahiye:** 5 quiz questions + 1 small change suggestion (code tu khud likhega, AI likhwayega nahi).
**Done check:** Tu quiz ke jawab de paya aur chhota change samajh ke kiya.
